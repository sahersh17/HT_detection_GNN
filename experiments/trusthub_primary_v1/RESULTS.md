Run date: 2026-11-03. This is a graph-only, golden-free development experiment on the locked 49-pair Trust-Hub primary view. All 11 families were previously inspected. The protocol in `protocol.json` was written before fitting these models. The 98 graph files were SHA-256 checked against the panel manifest. The five locked folds hold out entire families.

**Pre-set pass criterion: failed.** The graph-aggregate minus size paired interval includes zero. This is a resource gate on inspected development families, not a confirmatory population claim. The fixed-threshold classification results are poor. No full GNN run follows from this result. The local distance-tail fractions were a limited handcrafted control: controllability and observability graph-distance fractions at thresholds 8 and 16, divided by node count, alongside gate-class proportions. They do not measure dynamic toggling or true output reachability.

An exploratory metadata-only check fitted separate family-ID, exact source-bundle-ID, and synthesis-flow-ID logistic controls on the same folds. Each obtained 0.500 equal-family AUROC. All 98 test family and bundle IDs were unseen in training, so these identity checks are expected to be uninformative under the leave-family-out design. Flow ID was shared with training but constant within each held-out family. These controls do not eliminate synthesis-flow confounding in graph features. Per-circuit scores are in `metadata_controls.json`.

## Size audit

The positive graph has more nodes in 43 of 49 exact benchmark pairs. At a descriptive 5% mapped-node tolerance, positive-versus-negative comparisons exist in 10 families, excluding b15. The family-averaged matched-comparison accuracy is 0.741 for both size logistic and graph aggregates. These are 349 dependent cross-variant comparisons, not 349 independent circuits. Size can still rank records within the tolerance. The quartile analysis is in `data/trusthub_primary_v1/size_overlap.json`; its bins mix families and cannot isolate a within-family mechanism. The third quartile consists only of AES.

The registry's 55 extra clean records belong to other host families. They can test false positives on hard negatives, but cannot neutralize size for the 49 primary pairs. Creating benign, behavior-preserving additions on each clean Trust-Hub host requires new versioned sources, mapped-size checks, and functional verification. No such additions are claimed here.
