# Research direction and completion gates

## Validated position as of 2026-10-31

The strongest prospective research question is whether **gate evidence linked back to RTL makes Trojan localization and engineering explanations more accurate and useful** across unseen circuit designs. Detection is a prerequisite. The corrected source-traced development pilot gives fusion balanced accuracy 1.00 on 42 samples from only three clean-source groups, while an RTL-length-only control reaches 0.786. On ten samples from two previously reserved host designs, all four detection approaches—including fusion—score 0.50 balanced accuracy at the frozen threshold. This is a **generalization failure**, not evidence for a method claim. No reviewed gate labels or explanation ratings exist. See [CURRENT_RESULTS.md](CURRENT_RESULTS.md) and [LOCALIZATION_STATUS.md](LOCALIZATION_STATUS.md).

This direction needs a sharper contribution than combining a GNN and an LLM. [TrojanLoC](https://arxiv.org/abs/2512.00591) already studies RTL line localization, and [LoRD](https://arxiv.org/abs/2609.17922) reports strong gate localization with structural heuristics. The [ICCAD 2025 gate-level Trojan task](https://www.iccad-contest.org/2025/Problems.html) provides a relevant external comparison. The potential new contribution here is **verified gate-to-RTL provenance plus evidence-constrained trigger, payload, and fix explanations**, evaluated for localization and usefulness. This is a hypothesis, not a demonstrated result.

## Claim rules

- **Now:** a reproducible exploratory comparison, a source-tracing audit, and a measured cross-host detection failure. Do not claim proven localization, superior fusion, or correct explanations.
- **After stages 1–3:** a defensible labeled benchmark or annotation-method paper is possible, even if fusion remains weak, provided label coverage and reviewer agreement are credible.
- **After stages 4–6:** a method paper is plausible only if localization and explanation results improve on appropriate baselines on unseen hosts. If they do not, publish the negative finding or reposition around dataset/provenance engineering.
- **Without reviewers:** a paper may still report reproducible detection and source provenance, or machine-checked localization on a separately validated benchmark. It cannot claim engineer usefulness or expert-verified trigger, payload, and fix explanations. A polished demo must label unreviewed examples as candidates.

## Reproducible current artifact

Run `python pipeline/verify_artifact.py --pilot provenance_clean_pilot` and `python pipeline/provenance/publish_external.py --verify` to check saved predictions, scoring, sample membership, and input hashes. Run `python -m unittest discover -s pipeline/tests` for the utilities. Large source and model files are excluded from Git; their hashes are recorded, so verification requires local generated inputs. The old ZIP is needed for the earlier pilot, but the corrected source-traced pilot is a separate graph version.

## External inputs needed to finish the research claim

1. Independent semantic validation of the automatic gate/source candidates; the user has reported that hardware reviewers are unavailable. An alternative would be a separately published benchmark with validated node-level labels and a documented gate-to-RTL mapping. Neither is present here.
2. More independent clean host designs with licensed clean/Trojan variants and a genuinely untouched test set. `memctrl-T100` and four PIC16F84 variants have already been used in the diagnostic. They cannot be reserved again. `b15` pairs are not like-for-like RTL and require a separate conversion plan.
3. Hardware engineers for blinded explanation-usefulness assessment, if that claim remains a goal. Without them, omit that claim and focus on machine-checkable provenance or detection failure analysis.
4. A method that survives source-length and renaming controls and improves on strong baselines on new hosts. The current fusion model has not met this gate. The supplied ~240,000-node AES tensor version would additionally need its matching node metadata and compute to evaluate localization.

These are experimental dependencies. No code change can turn the current unreviewed source candidates into verified ground truth or create an untouched external test after the pilot has been inspected.
